A story-driven game framework built to make the boundary between visual novel and game disappear. Dialogue scenes use fully animated **VRM characters**, while the same runtime can transition into cinematic moments, spell-drawing challenges, maze exploration, and a real-time 3D dungeon encounter without changing engines.

The project is built with **React**, **Three.js**, and **Tauri**, with Zustand coordinating story state, choices, affection flags, audio, and minigame progression. Story content is organized as discoverable route and scene modules, so new chapters can be added without hard-coding them into the player.

![Dialogue scene with animated VRM characters](/projects/visual-novel/dialogue-preview.webp)

## Expressive 3D storytelling

Characters are rendered as live VRM models rather than static sprites. They support:

* Runtime expressions, active speakers, facial effects, and animation states.
* Procedural idle motion—breathing, head movement, eye motion, and posture shifts.
* Voice-driven lip sync with generated character voices and fallback behavior for unvoiced dialogue.
* Runtime attachments for props and accessories, including bone-relative transforms.

The presentation layer also supports branching choices, scene jumps, background effects, sound effects, BGM, affection flags, look-ahead asset preloading, and characters that remain visible while a minigame runs in a windowed dialogue layout.

## Cinematic scene system

Story beats can become authored cinematic compositions with layered backgrounds and foregrounds, parallax, camera motion, shader styles, particles, screen effects, and optional post-processing. A live cinematic editor exposes scene settings and effect controls while the game is running, making visual iteration much faster than editing static screenshots by hand.

![Layered cinematic scene preview](/projects/visual-novel/cinematic-preview.webp)

The renderer has both **WebGPU and WebGL paths**, quality profiles, adaptive pixel ratios, and surface-scoped post-processing for effects such as saturation, vignette, bloom, and SMAA. Asset cleanup, caching, and dungeon preloading keep transitions responsive as the scene changes from conversation to exploration.

## Playable systems inside the story

The engine currently registers several playable formats: crystal decryption, alphabet collection, maze exploration, spell casting with drawing recognition, and a procedural dungeon.

The dungeon has grown into a small combat framework rather than a placeholder prototype. It combines seeded procedural layouts, first-person exploration, objectives, collectibles, minimaps, enemy presets, party members, and a unified attack pipeline. Skills can target grid patterns, apply damage-over-time and status effects, spawn enemies, chain into multi-phase sequences, and resolve through distinct projectile, fireball, lightning, tsunami, sword-swing, and explosion effects.

## Stack

* **React + Zustand** — story flow, branching state, choices, flags, and UI.
* **Three.js / React Three Fiber / Drei** — VRM characters, environments, cameras, effects, and minigames.
* **WebGPU with WebGL fallback** — modern rendering with a compatibility path.
* **Tauri** — lightweight native desktop packaging.
* **Pixiv VRM + VRoid Studio** — runtime characters and custom anime-style models.
* **VoiceBox + Qwen3-TTS** — generated character voices connected to lip sync.

The project is still evolving toward its full story. The engine foundation is now in place: authored narrative content, cinematic presentation, and interactive gameplay all share the same state, rendering, and asset pipeline.
