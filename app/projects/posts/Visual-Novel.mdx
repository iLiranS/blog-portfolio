> **This project is still a work in progress.** Most of the current content exists to prototype engine features and gameplay systems before implementing the final story.

A desktop visual novel engine built entirely with modern web technologies. Instead of relying on traditional 2D sprites, the engine renders fully interactive **VRM 3D characters** in real time using **Three.js** (React Three Fiber + Drei), while the UI is built with **React**, **Tailwind CSS**, and **Tauri** for a lightweight native desktop experience.

The goal is to blend the presentation of a traditional visual novel with the interactivity of modern games, allowing the story to transition seamlessly into fully playable gameplay sections without changing engines or rendering pipelines.

# 🛠️ Tech Stack

* **Tauri** — Native desktop wrapper with a significantly smaller memory footprint than Electron.
* **React + Zustand** — Dialogue system, game state, branching choices, and UI management.
* **Three.js (React Three Fiber + Drei)** — Real-time 3D rendering, lighting, animations, and post-processing.
* **Tailwind CSS** — UI styling layered directly alongside the 3D scene.
* **Pixiv VRM** — Runtime loading and animation of VRM character models.
* **VRoid Studio** — Creation of custom anime-style characters.
* **VoiceBox + Qwen3-TTS** — AI-generated voice lines with custom character voices.

---

# 🎭 Fully Animated VRM Characters

Unlike traditional visual novels that use static sprites, every character is a fully rendered **VRM model**.

The engine currently supports:

* **Real-time lip sync** driven directly from voice audio, with fallback behavior for non-voiced dialogue.
* **Expression blending** with smooth interpolation instead of instant switching.
* **Character animations** and idle states.
* A procedural animation system that prevents characters from feeling static through subtle breathing, head movement, eye motion, and posture adjustments.

The goal is to make conversations feel closer to interacting with animated characters than reading static dialogue.

---

# 🗣️ AI Voice Pipeline

Every character can have a unique generated voice.

Voice lines are created using **VoiceBox**, powered by **Qwen3-TTS**, allowing new dialogue to be generated without recording voice actors during development.

Those generated voice lines are automatically synchronized with the lip-sync system so mouth movement closely matches the spoken audio.

# 🎮 Interactive Mini-Games

The engine supports both **fullscreen** and **windowed** mini-games.

Windowed mode allows gameplay to coexist with the visual novel interface, letting characters remain visible on top of the game and react in real time, making gameplay feel like part of the conversation rather than a separate mode.

Current examples include:

## Procedural Dungeon

A 3D exploration mini-game built on top of an excellent procedural dungeon generation project I found on GitHub and extended with my own gameplay systems.

My additions include:

* Player controller
* Character rendering
* Collectibles
* Exploration mechanics

The plan is to expand it further with enemies, objectives, combat, and additional progression systems.

## Drawing Recognition

Originally inspired by *Witch Hat Atelier*, this mini-game focuses on recognizing player-drawn symbols.

Instead of matching predefined shapes, the long-term goal is to allow intuitive drawings that carry meaning naturally.

The implementation is based on the **$N Recognition Algorithm**, extended with custom preprocessing such as grouping nearby strokes into unified shapes before recognition.

There are also several smaller mini-games used throughout the story, primarily to test engine capabilities and narrative pacing.

# 🤖 AI-Assisted Development

Much of the engine was developed alongside AI tools.

They significantly accelerated development, especially when building repetitive systems and prototypes. However, performance optimization, rendering architecture, and engine-level decisions still required substantial manual iteration, debugging, and refinement.

---

# ⚡ Performance

Rendering multiple animated 3D characters while maintaining responsive UI required several engine optimizations:

* Runtime asset and cache cleanup between scenes to avoid memory growth.
* Adaptive rendering resolution and configurable performance profiles.
* Careful resource management for VRM models and textures.
* Rendering techniques that allow characters to integrate cleanly with HTML-based interfaces without visual clipping.
